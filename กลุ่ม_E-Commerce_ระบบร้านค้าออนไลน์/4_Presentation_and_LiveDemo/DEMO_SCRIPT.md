# 🎬 สคริปต์การสาธิตระบบและบทพูดอย่างละเอียด (Comprehensive Live Demo Script)
**โครงการ:** ระบบร้านค้าออนไลน์ครบวงจร (E-Commerce Web Application)  
**สถาปัตยกรรม:** Laravel 11/13 + Bootstrap 5 + PostgreSQL (Supabase) / SQLite + Docker บน Render.com  
**เวลาสาธิตที่แนะนำ:** 7 - 10 นาที  
**รายชื่อและบทบาทสมาชิกในทีม:**
1. **หยาง (Yang)** - หัวหน้าทีม & DevOps & System Integration & Auth System
2. **พลับ (Plub)** - นักพัฒนาฝั่งหน้าบ้าน (Frontend UI & Shop Catalog)
3. **โชค (Chok)** - ผู้ดูแลฐานข้อมูลสินค้า & ระบบจัดการสินค้าหลังบ้าน (Products & Admin CRUD)
4. **กวาง (Kwang)** - ผู้พัฒนาระบบตะกร้าสินค้า & การสั่งซื้อ (Cart & Checkout Specialist)
5. **ปิงปอง (Pingpong)** - ผู้พัฒนาระบบผู้ใช้งาน & ระบบจัดการคำสั่งซื้อหลังบ้าน (User Profile & Admin Orders)

| **พลับ**<br>*(Frontend)* | **ถาม:** หน้าร้านรองรับ Responsive อย่างไร และดึงข้อมูลหมวดหมู่มาแสดงอย่างไร? | **ตอบ:** *"เราใช้ Grid System ของ Bootstrap 5 (`col-lg-*`, `col-md-*`) ร่วมกับ Custom CSS ทำให้หน้าเว็บปรับขนาดตามอุปกรณ์ทั้งมือถือและคอมพิวเตอร์อย่างสวยงาม ส่วนหมวดหมู่สินค้า เราใช้ Eloquent Query `Category::withCount('products')->get()` ทำให้ดึงหมวดหมู่พร้อมจำนวนสินค้าจริงมาแสดงได้ใน Query เดียว ช่วยลดปัญหา N+1 Query ครับ"* |
| **โชค**<br>*(Products)* | **ถาม:** แก้ปัญหาเรื่องรูปภาพสินค้าและการตั้งชื่อภาษาไทยอย่างไร? | **ตอบ:** *"สำหรับการอัปโหลดรูปภาพ เราเขียนโค้ดตรวจสอบและสร้างโฟลเดอร์ `public/images/products` อัตโนมัติ พร้อมตั้งชื่อไฟล์ใหม่ด้วย `time().'_'.uniqid()` ป้องกันชื่อไฟล์ซ้ำ ส่วนชื่อภาษาไทย ฟังก์ชัน `Str::slug()` ของ Laravel จะคืนค่าว่าง เราจึงเขียน Fallback Logic ให้สร้าง slug แบบ `product-` ตามด้วยเวลา และตรวจสอบความซ้ำใน DB เพื่อให้ได้ URL ที่ไม่ชนกันครับ"* |
| **กวาง**<br>*(Cart & Orders)* | **ถาม:** ถ้ามีลูกค้ากดสั่งซื้อสินค้าชิ้นสุดท้ายพร้อมกัน 2 คน จะเกิดอะไรขึ้น? | **ตอบ:** *"ระบบของเราใช้ **Database Transaction (`DB::transaction`)** ในการสั่งซื้อครับ เมื่อลูกค้ากดสั่งซื้อ ระบบจะตรวจเช็คสต็อก ณ เสี้ยววินาทีนั้น หากสต็อกไม่เพียงพอ ระบบจะโยน Exception และแจ้งเตือนลูกค้าว่าสินค้าไม่พอ พร้อม Rollback ยกเลิกรายการสั่งซื้อทั้งหมดทันที ทำให้สต็อกไม่มีวันติดลบ และไม่เกิดข้อผิดพลาดในการตัดเงินหรือสร้างใบสั่งซื้อครับ"* |
| **ปิงปอง**<br>*(User & Admin)* | **ถาม:** ป้องกันไม่ให้ลูกค้าทั่วไปแอบเข้าหน้า Admin ได้อย่างไร? | **ตอบ:** *"เราสร้าง **`AdminMiddleware`** ขึ้นมาคุ้มครอง Route กลุ่ม `/admin` ทั้งหมดครับ โดยตัว Middleware จะตรวจสอบ 2 ชั้น คือ 1. ต้องผ่านการล็อกอิน (`auth`) และ 2. เมธอด `$user->isAdmin()` ต้องคืนค่าเป็น `true` (เช็คฟิลด์ `is_admin == 1` หรือ `role == 'admin'`) หากลูกค้าทั่วไปพยายามเข้า URL หลังบ้าน ระบบจะปฏิเสธและเตือน 'Unauthorized Access' ทันทีครับ"* |
