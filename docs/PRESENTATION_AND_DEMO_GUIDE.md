# 🎤 แนวทางการนำเสนอผลงานหน้าชั้นเรียน & สคริปต์สาธิต (Live Demo Guide)
**โครงการ:** ระบบร้านค้าออนไลน์ (E-Commerce Web Application)  
**ทีมผู้พัฒนา:** หยาง, พลับ, โชค, กวาง, ปิงปอง  
**เวลาที่แนะนำในการนำเสนอ:** 8 - 12 นาที (สไลด์ 5 นาที + Live Demo 5-7 นาที)

---

## 1. การแบ่งบทบาทในการนำเสนอ (Team Roles for Presentation)

| ลำดับ | สมาชิก | หัวข้อในการนำเสนอ & สาธิต |
|---|---|---|
| 1 | **หยาง (Team Lead)** | เปิดการนำเสนอ, ภาพรวมโครงการ, สถาปัตยกรรมระบบ, Tech Stack, Git Workflow และสรุปภาพรวม |
| 2 | **พลับ (Frontend)** | หน้าเว็บหลัก (Home), หน้ารายการสินค้า (Shop), ระบบค้นหา, กรองราคา, และหน้าดูรายละเอียดสินค้า |
| 3 | **กวาง (Cart & Orders)** | ระบบตะกร้าสินค้า (Cart), ขั้นตอนการสั่งซื้อ (Checkout), การตัดสต็อกสินค้า และประวัติคำสั่งซื้อ |
| 4 | **โชค (Products)** | ระบบหลังบ้าน Admin: การจัดการหมวดหมู่สินค้า (Categories) และการเพิ่ม/แก้ไขสินค้าพร้อมอัปโหลดรูป |
| 5 | **ปิงปอง (User & Admin)** | Admin Dashboard ภาพรวมสถิติ, การจัดการออเดอร์ (เปลี่ยนสถานะ), การจัดการผู้ใช้ และระบบโปรไฟล์ |

## 2. โครงร่างสไลด์การนำเสนอ (Slide Deck Outline - 10 สไลด์)

### สไลด์ที่ 1: หน้าปก (Title Slide)
- **หัวข้อ:** โครงการพัฒนาระบบร้านค้าออนไลน์ (E-Commerce Web Application)
- **รายชื่อสมาชิกในทีม:**
  1. หยาง (Team Lead / DevOps & Auth)
  2. พลับ (Frontend Developer)
  3. โชค (Product Management)
  4. กวาง (Cart & Order System)
  5. ปิงปอง (User Profile & Admin)
- **สถาบัน:** มหาวิทยาลัยราชภัฏเชียงใหม่

### สไลด์ที่ 2: ที่มาและความสำคัญ (Problem & Motivation)
- การเติบโตของการค้าออนไลน์ (E-Commerce) ในปัจจุบัน
- ความต้องการระบบร้านค้าที่ใช้งานง่าย รวดเร็ว รองรับการค้นหาสินค้าที่แม่นยำ
- ปัญหาที่พบบ่อยในระบบทั่วไป: สต็อกสินค้าไม่ตัดจริง, ข้อมูลคำสั่งซื้อไม่สัมพันธ์กับสินค้า, ผู้ดูแลระบบจัดการยาก

### สไลด์ที่ 3: สถาปัตยกรรม & เทคโนโลยีที่ใช้ (Tech Stack)
- **Backend:** Laravel 11 (PHP 8.2+) สถาปัตยกรรม MVC
- **Frontend:** Blade Templates, Bootstrap 5, Bootstrap Icons, Vanilla CSS
- **Database:** Supabase (PostgreSQL) / SQLite Database
- **Authentication & Security:** Laravel Breeze, Bcrypt Password Hashing, CSRF Protection
- **Version Control:** Git & GitHub (ทำงานแยก Branch 5 คน: `feature/auth`, `feature/frontend`, `feature/products`, `feature/cart-orders`, `feature/admin`)

### สไลด์ที่ 4: การออกแบบฐานข้อมูล (Database Design & ER-Diagram)
- นำเสนอแผนภาพ **ER-Diagram** (6 ตารางหลัก):
  - `users` ➔ `carts` ➔ `products`
  - `categories` ➔ `products`
  - `users` ➔ `orders` ➔ `order_items` ➔ `products`
- อธิบายการใช้ Foreign Key, Cascade Delete, และ Unique Constraint ป้องกันข้อมูลซ้ำซ้อน

### สไลด์ที่ 5: ฟังก์ชันหลักฝั่งลูกค้า (Customer Journey Features)
- ค้นหาสินค้าแบบ Real-time ตามชื่อ, หมวดหมู่ และช่วงราคา
- ตะกร้าสินค้าแสดงจำนวนแบบไดนามิกบน Navbar
- สั่งซื้อสินค้าพร้อมบันทึกที่อยู่จัดส่งและตัดสต็อกสินค้าทันที
- ติดตามสถานะคำสั่งซื้อแบบแบ่งรหัสสีเข้าใจง่าย (รอชำระ, ดำเนินการ, จัดส่ง, สำเร็จ)

### สไลด์ที่ 6: ฟังก์ชันหลักฝั่งผู้ดูแลระบบ (Admin Panel Features)
- แดชบอร์ดสรุปยอดขายรวม, จำนวนออเดอร์, จำนวนสินค้า, และจำนวนสมาชิก
- จัดการหมวดหมู่และสินค้าแบบครบวงจร (CRUD) พร้อมอัปโหลดรูปภาพ
- จัดการคำสั่งซื้อและเปลี่ยนสถานะออเดอร์ได้ทันที
- จัดการสิทธิ์ผู้ใช้งาน (User / Admin)

### สไลด์ที่ 7: จุดเด่นและเทคนิคทางโปรแกรมมิ่ง (Technical Highlights)
- **Database Transactions:** ควบคุมการสั่งซื้อและตัดสต็อก ป้องกันข้อผิดพลาดกรณีสต็อกสินค้าไม่พอ
- **Snapshot Pricing:** บันทึกราคาและชื่อสินค้า ณ เวลาสั่งซื้อในตาราง `order_items` เพื่อป้องกันปัญหายอดเงินเปลี่ยนเมื่อสินค้าราคาเปลี่ยนในอนาคต
- **Thai Unicode Slug Fallback:** รองรับการสร้าง URL Slug สำหรับชื่อภาษาไทยโดยไม่ทำให้ระบบ Error
- **Automated Directory Generator:** ตรวจสอบและสร้างโฟลเดอร์สำหรับเก็บไฟล์รูปภาพอัตโนมัติเมื่อมีการอัปโหลด

### สไลด์ที่ 8: การทดสอบคุณภาพระบบ (Quality Assurance & Automated Testing)
- พัฒนาชุดทดสอบอัตโนมัติด้วย **PHPUnit / Pest**
- ผ่านการทดสอบ **100% (40 Tests, 110 Assertions)**
- ครอบคลุมทั้งระบบ Auth, Profile, Frontend, Admin, และ Cart & Order Workflow

### สไลด์ที่ 9: บทเรียนที่ได้รับและการทำงานร่วมกัน (Teamwork & Retrospective)
- การทำงานร่วมกันผ่าน Git Branching Strategy (Feature Branch ➔ Develop ➔ Main)
- การแก้ปัญหา Merge Conflicts อย่างเป็นระบบ
- การวาง Database Schema ล่วงหน้าช่วยให้ทุกคนพัฒนาโค้ดไปในทิศทางเดียวกัน

### สไลด์ที่ 10: สรุปผลและถาม-ตอบ (Conclusion & Q&A)
- สรุปความสำเร็จของโปรเจกต์
- ขอบคุณอาจารย์และเพื่อนๆ พร้อมเข้าสู่ช่วง Live Demo และตอบข้อซักถาม

## 3. สคริปต์และขั้นตอนการสาธิตการทำงานจริง (Live Demo Script)

> **การเตรียมตัวก่อน Demo:**
> 1. รันเซิร์ฟเวอร์ไว้ล่วงหน้า: `php artisan serve` (เปิดที่ `http://127.0.0.1:8000`)
> 2. เตรียมเปิดบราวเซอร์ 2 แท็บ:
>    - แท็บที่ 1: โหมดไม่ระบุตัวตน (Incognito) สำหรับสาธิตฝั่งลูกค้า (User)
>    - แท็บที่ 2: หน้าต่างปกติสำหรับล็อกอินเป็น Admin (`admin@example.com`)

---

### ขั้นตอนที่ 1: แนะนำหน้าบ้านและการเลือกชมสินค้า (ผู้บรรยาย: พลับ)
1. **เปิดหน้าแรก (`/`):**
   - *"สวัสดีครับอาจารย์ ในส่วนแรกเรามาดูหน้าแรกของร้านค้า มีการแสดงแบนเนอร์ หมวดหมู่สินค้า และสินค้าใหม่ล่าสุด 8 รายการ"*
2. **ไปหน้าร้านค้า (`/shop`):**
   - *"เมื่อคลิกที่เมนู 'สินค้า' ด้านบน จะเข้าสู่หน้าแสดงสินค้าทั้งหมด ซึ่งมีระบบแบ่งหน้า (Pagination) 12 รายการ"*
3. **ทดสอบค้นหาและกรองสินค้า:**
   - พิมพ์ในช่องค้นหา: `เสื้อ` ➔ แสดงเฉพาะเสื้อ
   - เลือกหมวดหมู่ `เครื่องมือช่าง` ➔ แสดงสินค้าเครื่องมือช่าง
   - ปรับช่วงราคา เช่น `100` ถึง `500` บาท ➔ แสดงสินค้าในช่วงราคา
4. **คลิกดูรายละเอียดสินค้า:**
   - คลิกสินค้า `เสื้อยืดแขนสั้น Cotton 100%`
   - แสดงราคา 350.00 บาท สต็อกคงเหลือ และมีปุ่มเพิ่ม/ลดจำนวนชิ้น

---

### ขั้นตอนที่ 2: การสั่งซื้อสินค้าและตัดสต็อก (ผู้บรรยาย: กวาง)
1. **เพิ่มสินค้าลงตะกร้า:**
   - เลือกจำนวน 2 ตัว ➔ กดปุ่ม **"เพิ่มลงตะกร้า"**
   - สังเกตที่ไอคอนตะกร้าบน Navbar จะมีป้ายตัวเลขสีแดงปรากฏขึ้นทันที
2. **เปิดหน้าตะกร้าสินค้า (`/cart`):**
   - แสดงรายการเสื้อยืด 2 ตัว ยอดรวม 700 บาท
   - ลองปรับจำนวนเป็น 3 ตัวแล้วกดบันทึก ➔ ยอดรวมเปลี่ยนเป็น 1,050 บาท อย่างถูกต้อง
3. **ไปหน้าสั่งซื้อสินค้า (Checkout):**
   - กดปุ่ม "ไปหน้าสั่งซื้อสินค้า"
   - กรอกข้อมูลจัดส่ง: ชื่อ "สมชาย ใจดี", เบอร์โทร "081-234-5678", ที่อยู่ "123 ม.1 ต.ช้างเผือก อ.เมือง จ.เชียงใหม่"
   - กดปุ่ม **"ยืนยันการสั่งซื้อ"**
4. **ตรวจสอบผลลัพธ์คำสั่งซื้อ:**
   - ระบบสร้างเลขอ้างอิงออเดอร์ เช่น `ORD-20260922-XXXX`
   - สถานะคำสั่งซื้อเริ่มต้นเป็น **"รอชำระเงิน" (Pending)**
   - สต็อกสินค้าของเสื้อยืดลดลงทันที 3 ตัว

---

### ขั้นตอนที่ 3: ระบบหลังบ้าน Admin จัดการออเดอร์และสินค้า (ผู้บรรยาย: โชค & ปิงปอง)
1. **สลับไปแท็บ Admin Dashboard (`/admin`):**
   - *"เมื่อล็อกอินด้วยบัญชีแอดมิน ระบบจะพาเข้าสู่หน้า Admin Dashboard ทันที"*
   - ชี้ให้เห็นตัวเลขสถิติ: ยอดขาย, จำนวนออเดอร์ที่เพิ่งเพิ่มขึ้นมา, สินค้าทั้งหมด และสมาชิก
2. **จัดการคำสั่งซื้อ (`/admin/orders`):**
   - คลิกที่ออเดอร์ล่าสุดของ "สมชาย ใจดี"
   - แสดงรายการสินค้า ราคา ที่อยู่จัดส่ง
   - ผู้ดูแลระบบเปลี่ยนสถานะเป็น **"กำลังดำเนินการ" (Processing)** หรือ **"จัดส่งแล้ว" (Shipped)** แล้วกดปุ่ม "อัปเดตสถานะ"
3. **จัดการสินค้าและหมวดหมู่ (`/admin/products`):**
   - แสดงรายการสินค้าทั้งหมด
   - สาธิตการกด "เพิ่มสินค้าใหม่" กรอกชื่อภาษาไทย, ราคา, สต็อก และอัปโหลดไฟล์รูปภาพ
   - บันทึกแล้วสินค้าแสดงผลในระบบทันที

### ขั้นตอนที่ 4: ตรวจสอบความถูกต้องฝั่งลูกค้า & ติดต่อเรา (ผู้บรรยาย: ปิงปอง & หยาง)
1. **กลับมาที่หน้าจอของลูกค้า:**
   - ไปที่เมนู "คำสั่งซื้อ" ➔ รีเฟรชหน้าจอ จะเห็นสถานะออเดอร์เปลี่ยนเป็น **"จัดส่งแล้ว"** ตามที่แอดมินอัปเดต
2. **เปิดหน้า "ติดต่อเรา" (`/contact`):**
   - แสดงรายชื่อและบทบาทของสมาชิกทีมพัฒนาทั้ง 5 คน (หยาง, พลับ, โชค, กวาง, ปิงปอง) พร้อมข้อมูลช่องทางติดต่อและฟอร์มส่งข้อความ
3. **สรุปการนำเสนอ:**
   - หยางกล่าวสรุป: *"ระบบทำงานสอดประสานกันอย่างสมบูรณ์แบบทั้งฝั่งลูกค้าและผู้ดูแลระบบ ขอจบการนำเสนอและเปิดรับคำแนะนำจากอาจารย์ครับ"*

## 4. แนวทางการตอบคำถามที่อาจารย์มักจะถาม (Anticipated Q&A)

**Q1: ถ้ามีลูกค้ากดสั่งซื้อสินค้าชิ้นสุดท้ายพร้อมกัน 2 คน ระบบจัดการอย่างไร?**  
*แนวทางการตอบ:*  
> "เราใช้ **Database Transaction (`DB::transaction`)** ใน `OrderController` พร้อมตรวจสอบสต็อกคงเหลือ หากมีคนสั่งตัดสต็อกไปก่อนจนเหลือ 0 ระบบจะ rollback และแสดงข้อความแจ้งเตือนลูกค้าอีกคนทันทีว่าสินค้าในสต็อกไม่เพียงพอ ทำให้สต็อกไม่ติดลบแน่นอนครับ"

**Q2: ถ้าภายหลังร้านค้ามีการปรับขึ้นราคาสินค้า ประวัติออเดอร์เดิมของลูกค้าจะเปลี่ยนราคาตามไหม?**  
*แนวทางการตอบ:*  
> "ไม่เปลี่ยนครับ เพราะเราออกแบบตาราง `order_items` ให้บันทึกราคาและชื่อสินค้าแบบ **Snapshot** ณ วินาทีที่สั่งซื้อแยกต่างหากจากตาราง `products` ทำให้ประวัติการเงินถูกต้องเสมอครับ"

**Q3: มีการป้องกันความปลอดภัยอย่างไรบ้าง?**  
*แนวทางการตอบ:*  
> "เราใช้ **Laravel Breeze** สำหรับการเข้ารหัสผ่านแบบ Bcrypt, มี **CSRF Token** ป้องกันทุกฟอร์ม, มี **AdminMiddleware** ตรวจสอบสิทธิ์ก่อนเข้าถึงหน้า `/admin` และใช้ **Eloquent ORM Parameter Binding** เพื่อป้องกัน SQL Injection ทั้งหมดครับ"
